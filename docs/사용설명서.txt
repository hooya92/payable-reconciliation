PayableRecon 사용설명서
미지급금 대사 및 당월 명세서 생성

PayableRecon.zip의 압축을 풀면 다음 두 파일이 나옵니다.
- PayableRecon.exe: 프로그램 실행파일
- 사용설명서.txt: 본 설명서

1. 프로그램 소개

전월 말 미지급금 명세서와 당월 더존 Raw를 비교하여
당월 말 미지급금 명세서 초안을 만드는 Windows 프로그램입니다.

거래처코드, 금액, 적요 등을 확인하여 대사하고,
담당자가 확인해야 할 항목과 사유를 표시합니다.
입력 파일은 읽기만 하며, 결과는 별도 Excel 파일로 저장합니다.
더존에 전표를 입력하거나 원본 데이터를 수정하지 않습니다.

2. 준비할 파일

[전월 명세서]
- 전월 말 기준으로 확인이 끝난 미지급금 명세서
- 코드, 거래처, 적요, 금액이 포함된 기존 양식
- 당월 명세서 생성에는 .xlsx 파일 1개를 사용합니다.
- .xls 또는 .xlsm 파일은 Excel에서 .xlsx로 복사 저장합니다.

[더존 Raw]
- 생성할 당월의 미지급금 계정 전표출력 Excel
- 기표일자, 계정코드, 거래처코드, 거래처명, 적요, 차변, 대변 포함
- 여러 파일을 첨부할 수 있지만 같은 전표가 겹치지 않도록 준비합니다.

예: 2026년 8월 명세서 생성
    → 2026년 7월 말 명세서 + 2026년 8월 더존 Raw

[확장자 지원 범위]
- .xlsx: 입력·대사 및 전월 양식 기반 당월 명세서 생성 지원
- .xlsm: 입력·대사 지원, 매크로는 실행하지 않음
- .xls: 입력·대사 지원, 수식이 포함된 파일은 처리를 중단함
- .xlsm/.xls 전월 양식: 당월 명세서 생성 전 .xlsx로 복사 저장
- .csv/.xlsb/.ods: 미지원
- 생성 결과: .xlsx

확장자 이름만 바꾸지 말고 Excel의 '다른 이름으로 저장'을 사용합니다.

3. 사용 순서

① PayableRecon.exe를 실행합니다.
② '명세서'에 전월 말 명세서를 첨부합니다.
③ '더존 Raw'에 당월 원장 파일을 첨부합니다.
④ 자동 감지된 대상 회계월을 확인합니다.
⑤ 회사에서 사용하는 미지급금 계정코드를 확인합니다.
   기본값은 25301이며, 여러 개면 쉼표로 구분합니다.
⑥ '대사 시작'을 누르고 결과와 입력 확인 항목을 확인합니다.
⑦ '당월 명세서 생성'을 누르고 새 파일명과 저장 위치를 지정합니다.
⑧ 저장이 완료되면 저장 폴더가 자동으로 열립니다.
   Excel 파일은 직접 열어 내용을 검토합니다.

원본 파일과 동일한 경로로 덮어쓰기는 할 수 없습니다.

4. 당월 명세서 작성 방식

전월 명세서의 상세 내역과 기존 서식을 바탕으로 작성합니다.
당월 더존 Raw의 대변은 양수, 차변은 음수로 추가합니다.
발생·지급 내역은 남기고 거래처별 소계를 다시 계산합니다.

당월 소계 = 전월 상세 합계 + 당월 대변 - 당월 차변

예: 전월 잔액 900,000원 + 당월 발생 250,000원 - 지급 400,000원
    = 당월 잔액 750,000원

명세서 금액을 더존 금액으로 임의 교체하지 않습니다.
두 파일의 내용 차이와 불확실한 연결은 검토 사유로 표시합니다.

처리상태는 기존 표 오른쪽에 표시합니다.
표가 E열까지면 F열이며, 그 오른쪽에 기존 메모 등이 있으면
기존 데이터 뒤의 빈 열을 사용합니다.

5. 처리상태 읽는 방법

[자동 대사]
전월 발생 내역과 당월 지급 전표가 대사 조건에 따라 연결된 상태입니다.

[전월 이월]
대사에 사용한 당월 Raw에서 대응 지급이 확인되지 않은 전월 내역입니다.

[당월 신규]
당월 Raw의 대변 내역으로 신규 발생으로 분류된 항목입니다.

[당월 지급]
당월 Raw의 차변 내역입니다.
어떤 전월 발생 건에 대한 지급인지는 아직 확정되지 않을 수 있습니다.

[순잔액 대사]
전월에 양수 발생과 음수 지급·조정이 함께 있는 거래처에서
전월 상세 합계와 소계를 검증하고 당월 순잔액을 계산한 상태입니다.
개별 청구 건과 지급 건이 하나씩 연결됐다는 뜻은 아닙니다.

[확인 필요 / 오타 의심]
거래처코드·거래처명 차이, 적요 차이, 부분지급, 중복·분할,
금액 수식, 입력 오류, 음수 잔액 등의 확인이 필요한 상태입니다.
처리상태에 붙은 사유, 셀 메모, '검토필요' 시트를 함께 확인합니다.

[원장 단독]
전월 명세서의 대응 내역 등이 확인되지 않은 Raw 차변입니다.
전월 누락, 조정 또는 지급 성격을 확인합니다.

[소계]
해당 거래처에 표시된 상세 금액의 합계입니다.

6. 결과 파일의 시트

[당월 시트: 예시 26.08]
전월 양식을 바탕으로 만든 당월 명세서 본문입니다.

[대사내역]
연결된 전월 발생 내역과 당월 지급 전표의 일치 후보를 보여줍니다.
자동 대사는 실제 상계 확정이나 회계 처리 승인을 의미하지 않습니다.

[검토필요]
담당자가 확인해야 할 항목, 사유, 출처를 모아 보여줍니다.

[변경내역]
전월에서 유지한 행과 당월 Raw에서 추가한 행의 반영 내역입니다.
금액, 반영 근거, 원본 파일명과 원본 행 번호를 확인할 수 있습니다.
Excel에서 담당자가 직접 수정한 셀의 변경 이력을 기록하지는 않습니다.

'원본행' 링크가 있는 번호를 누르면 생성된 당월 명세서의
해당 거래 행으로 이동합니다. 표시된 번호는 원본 파일 기준입니다.

7. 검토 및 다음 달 사용

① '검토필요'의 사유를 확인하고 해당 거래 내역을 점검합니다.
② 거래처별 소계를 더존 원장과 대조합니다.
③ 입력 파일의 문제라면 입력을 수정한 후 대사를 다시 실행하고
   당월 명세서를 다시 생성합니다.
④ 담당자 확인을 마친 본문과 소계를 저장합니다.
⑤ 검토 기록은 별도로 보관한 후 필요에 따라 보조 시트를 삭제합니다.

검토 항목이 남은 생성 파일을 다음 달 전월 명세서로 첨부하면
프로그램이 진행을 중단합니다. 실제 검토와 필요한 수정을 마친 후
'검토필요' 시트를 삭제한 확정 파일을 사용합니다.
시트 삭제 자체가 오류를 해결하거나 검토를 완료하는 것은 아닙니다.

8. 자주 나오는 안내

[파일 접근 거부]
저장할 결과 파일을 Excel에서 닫고 다시 저장합니다.
계속 실패하면 다른 파일명이나 쓰기 가능한 폴더를 선택합니다.

[대사 후 입력 파일 변경]
입력 파일 수정 내용을 반영하려면 대사를 다시 실행합니다.

[회계월 확인]
전월 말 명세서와 당월 Raw가 이어지는 월인지 확인합니다.

[입력 오류로 자동 확정 보류]
명세서 오류의 거래처를 명확히 식별하면 해당 거래처를 보류합니다.
거래처를 식별할 수 없거나 Raw 입력 오류가 있으면
다른 항목의 자동 확정에도 영향을 줄 수 있습니다.
입력 확인 사유와 원본 행을 확인한 후 다시 실행합니다.

[텍스트 음수와 금액 수식]
'-       170000' 같은 부호 뒤 공백이 있는 텍스트 음수는 읽습니다.
단순 상수 수식과 확인 가능한 소계 SUM은 계산합니다.
숫자 사이의 비정상 공백이나 계산값을 확정할 수 없는 수식은
검토가 필요할 수 있습니다.

[날짜가 다른 내역]
장기 이월 내역을 고려하여 전월 상세 행의 날짜는 대사키로 쓰지 않습니다.
회계월 선택과 Raw 대상월 확인은 별도로 수행합니다.
